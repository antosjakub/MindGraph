High: generic “Connect mode” is effectively broken unless a source node is already selected. `toggleConnectMode()` sets only `state.connectMode = true` and shows “Click a node to start connecting”, but leaves `state.connectFrom = null` ([app.js](/home/antos_j/MindGraph/app.js:1088)). The first click on any node then goes through the `state.connectMode && target` branch and calls `finishConnection(target.dataset.id)` ([app.js](/home/antos_j/MindGraph/app.js:842)), which immediately cancels because `state.connectFrom` is falsy ([app.js](/home/antos_j/MindGraph/app.js:450)). That means the advertised toolbar/keyboard flow in [index.html](/home/antos_j/MindGraph/index.html:50) and [README.md](/home/antos_j/MindGraph/README.md) does not actually let you start a connection from scratch.

2. High: the leftover Perplexity inline-edit script can leak a screenshot of the user’s notes to any embedding parent. The handler accepts `postMessage` events from any origin, does no origin validation, and replies with `postMessage(..., '*')` after rasterizing the page ([index.html](/home/antos_j/MindGraph/index.html:149)). Given `PURPOSE.md` describes this as a personal math/physics notes app ([PURPOSE.md](/home/antos_j/MindGraph/PURPOSE.md:1)), shipping an unauthenticated screenshot bridge is a real privacy problem.

3. Medium: note content is rendered as unsanitized HTML. `renderMd()` feeds processed note text straight into `marked.parse()` ([app.js](/home/antos_j/MindGraph/app.js:67)), and the result is assigned with `innerHTML` in at least three places ([app.js](/home/antos_j/MindGraph/app.js:128), [app.js](/home/antos_j/MindGraph/app.js:237), [app.js](/home/antos_j/MindGraph/app.js:480)). A pasted payload like raw HTML with event handlers can execute in the app’s origin. For a personal notes tool, that is avoidable and risky.

Low: connection-mode UI state is inconsistent and can leave stale highlighting behind. `startConnection()` enables connect mode but never marks the toolbar button active ([app.js](/home/antos_j/MindGraph/app.js:443)), while `cancelConnection()` removes the temp path but does not clear `.connect-target` classes or the active button ([app.js](/home/antos_j/MindGraph/app.js:466)). After cancelling, a node can remain visually highlighted and the button state can disagree with actual mode.

5. High: every screen→world conversion is off by 44px vertically because the 44px header offset of `#canvasArea` ([style.css](/home/antos_j/MindGraph/style.css:131)) is never subtracted from `e.clientY`. `screenToWorld()` ([app.js](/home/antos_j/MindGraph/app.js:102)) treats clientY as canvas-relative, so a double-click ([app.js](/home/antos_j/MindGraph/app.js:1076)) drops a node ~44px below the cursor, and `addNode` via the `N` key / toolbar ([app.js](/home/antos_j/MindGraph/app.js:1041), [app.js](/home/antos_j/MindGraph/app.js:1084)) mis-centers similarly. The shift-drag selection rect is drawn from clientX/Y on a `position: fixed` element ([style.css](/home/antos_j/MindGraph/style.css:162)) but `selectNodesInRect()` compares against canvas-relative `node.y * zoom + vy` ([app.js](/home/antos_j/MindGraph/app.js:432)), so the rect picks up nodes that are visually 44px lower than what it's covering. The wheel-zoom pivot has the same mismatch in `setZoom()` ([app.js](/home/antos_j/MindGraph/app.js:666)). The temporary connection line in `mousemove` mixes canvas-space `cx,cy` with viewport-space `mx = e.clientX, my = e.clientY` ([app.js](/home/antos_j/MindGraph/app.js:935)), so the dangling line trails the cursor by 44px. Fix: subtract `canvas.getBoundingClientRect().top` (and `.left`, for symmetry) from any clientY before treating it as canvas/world space.

6. Medium: `fitView()` adds a stray `+ 44` to the y centering formula ([app.js](/home/antos_j/MindGraph/app.js:704)). Deriving the correct math against the actual render pipeline (`world.y * zoom + 44 + viewport.y`), the constant should be removed entirely — the current expression centers the bounding box ~66px below the visual center of the canvas. The "no nodes" branch on [app.js](/home/antos_j/MindGraph/app.js:682) is also off (it uses `(window.innerHeight + 44) / 2` where `(window.innerHeight - 44) / 2` is correct), and disagrees with the empty-board default in `loadBoard` ([app.js](/home/antos_j/MindGraph/app.js:745)) which uses `window.innerHeight / 2` and a leftover `- 80` on x. All three should agree on one formula.

7. High: switching boards can silently drop the previous board's edits. `loadBoard()` calls `saveCurrentBoard()` ([app.js](/home/antos_j/MindGraph/app.js:728)) which only updates the in-memory `board.data`, then immediately persists `mindgraph_active` to storage ([app.js](/home/antos_j/MindGraph/app.js:732)). The board data itself never reaches localStorage until the next `save()` (autosave is on a 10s interval, [app.js](/home/antos_j/MindGraph/app.js:1180)). If the user switches boards and closes the tab within 10s, the prior board's changes are lost while the active-board pointer has already moved. Replace the `saveCurrentBoard()` call in `loadBoard` with `save()`.

8. Medium: shift-drag rectangle replaces the selection instead of adding to it. On mouseup, the `isSelecting` branch ([app.js](/home/antos_j/MindGraph/app.js:972)) calls `clearSelection()` before `selectNodesInRect(...)`. Shift is universally the "additive" modifier and the README advertises "Shift+drag | Rectangle select" alongside "Shift+click | Multi-select" ([README.md](/home/antos_j/MindGraph/README.md:20)), so the two should behave consistently. Drop the `clearSelection()` call.

9. Low: shift-click on an already-selected node deselects it but still enters drag mode. In the canvas `mousedown` handler ([app.js](/home/antos_j/MindGraph/app.js:852)), the shift branch calls `deselectNode(nodeId)` and falls through to set `state.isDragging = true`, add the `grabbing` cursor, and build `_dragInitial` from the (now-shrunk) selection ([app.js](/home/antos_j/MindGraph/app.js:864)). Nothing moves on the subsequent `mousemove` because the clicked node is no longer in `state.selected`, but the cursor lies and `mouseup` runs `save()` unconditionally ([app.js](/home/antos_j/MindGraph/app.js:962)). After `deselectNode` in the shift branch, return early instead of starting drag setup.

10. Low: KaTeX output collides with markdown. `renderMd()` calls `katex.renderToString()` first and then pipes the resulting HTML through `marked.parse()` ([app.js](/home/antos_j/MindGraph/app.js:67)). Marked rewrites underscores inside the rendered HTML (class names, attribute values, escaped TeX) as `<em>` tags, which breaks visible math whenever a formula contains `_`. Fix: stash KaTeX output behind unique placeholder tokens before `marked.parse`, then swap the HTML back in afterwards.

The conditional class never fires; either wire up group selection or drop the dead branch.
